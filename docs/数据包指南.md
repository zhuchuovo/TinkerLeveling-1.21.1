# 匠魂等级（Tinker Leveling）数据包指南

本模组的等级与槽位规则全部由数据包驱动。**不装数据包时，行为与旧版一致**：经验曲线取自
`config/tinkerleveling-server.toml`，每升一级获得 1 个强化槽（拆分方式等同旧版的 `能力 = n/2`、`升级 = n - n/2`，通过 NBT 迁移保证老存档不丢槽位）。

---

## 1. 文件放在哪里

```
<存档>/datapacks/<你的包>/
├── pack.mcmeta
└── data/<命名空间>/tinkerleveling/leveling/
    ├── default.json
    ├── ranged_tools.json
    └── ...
```

- 目录固定为 `tinkerleveling/leveling`，文件名任意（即规则 ID：`<命名空间>:<文件名>`）。
- 修改后执行 `/reload` 即可生效，**不需要重启游戏**。
- 加载失败的规则会在日志里报错并被跳过，受影响的工具回退到配置文件默认值。

`pack.mcmeta`：

```json
{
  "pack": {
    "pack_format": 48,
    "description": "Tinker Leveling rules"
  }
}
```

> 1.21.1 的 `pack_format` 是 `48`；数据包放 `datapacks/` 时这个字段其实不会被严格校验。

## 2. 规则文件结构

```json
{
  "priority": 0,
  "tool": { "tag": "tconstruct:modifiable/ranged" },
  "xp": { "base": 500, "multiplier": 2.0 },
  "max_level": 20,
  "slots": [
    { "levels": { "min": 1, "max": 4 }, "mode": "grant",  "slots": ["upgrades", "upgrades"] },
    { "levels": { "min": 5 },           "mode": "choose", "slots": ["abilities", "upgrades"] }
  ]
}
```

### 顶层字段

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `priority` | 整数 | `0` | 优先级，**数值大的先匹配**。同一把工具只应用第一条命中的规则。 |
| `tool` | 工具谓词 | 全部工具 | 这条规则作用于哪些工具，见第 3 节。 |
| `xp` | 对象 | 用配置文件 | 经验曲线。 |
| `max_level` | 整数 | `-1` | 等级上限，`-1` 表示沿用配置文件。**只会比配置文件更严格，不会突破它。** |
| `slots` | 数组 | 空 | 升级时的槽位奖励，见第 4 节。 |

### `xp` 对象

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `base` | 小数 | 配置文件 `defaultBaseXP` | 从 1 级升到 2 级所需经验。 |
| `multiplier` | 小数 | 配置文件 `levelMultiplier` | 每高一级，所需经验乘以该系数。 |

升级所需经验 = `base × multiplier^(当前等级 - 1)`。

只想改经验、保留默认槽位时，可以整条规则只写 `xp`：

```json
{ "tool": { "tag": "tconstruct:modifiable/harvest" }, "xp": { "base": 300 } }
```

### `slots` 数组元素

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `levels` | 对象 | **必填** | `{"min": 1, "max": 4}`，闭区间；省略 `max` 表示"及以上"。 |
| `mode` | 字符串 | `grant` | `grant` = 直接发放；`choose` = 让玩家自己挑。 |
| `slots` | 字符串数组 | **必填** | 槽位类型列表。`grant` 时**每个元素各发 1 个**；`choose` 时表示**可选项**。 |

### 槽位类型可用值

| 写法 | 匠魂内部名 |
|---|---|
| `upgrades` 或 `upgrade` | 强化槽 |
| `abilities` 或 `ability` | 能力槽 |
| `defense` 或 `defence` | 防御槽（盔甲） |
| `souls` 或 `soul` | 灵魂槽 |

> 写错的槽位名会**在加载时报错并跳过整条规则**，而不是悄悄生成一个用不了的槽位类型。
> 这一点比匠魂原生的 `SlotType.LOADABLE` 更严格，目的是让拼写错误立刻暴露。

### `mode` 的行为

**`grant`（默认）** —— 数组里每一项各发 1 个：

```json
{ "levels": { "min": 1, "max": 4 }, "mode": "grant", "slots": ["upgrades"] }
```

1~4 级每级给 1 个强化槽。想每级给 3 个就写 `["upgrades", "upgrades", "upgrades"]`。

**`choose`** —— 玩家从可选项里挑一个，**升级会暂停直到选完**：

```json
{ "levels": { "min": 5 }, "mode": "choose", "slots": ["abilities", "upgrades"] }
```

5 级起弹窗让玩家二选一。选中的那 1 个立即生效，其余选项作废。
可选项只剩一个时不会弹窗，直接发放。

> ⚠️ `choose` 规则挂起时，该工具**不再累积经验**。这是有意设计：避免玩家一直不选、把奖励堆起来。

## 3. 怎么区分工具（`tool` 谓词）

`tool` 用的是匠魂自己的工具谓词系统，可以直接复用匠魂全部写法。

### 按标签（最常用）

```json
"tool": { "tag": "tconstruct:modifiable/ranged" }
```

常用标签：

| 标签 | 覆盖内容 |
|---|---|
| `tconstruct:modifiable` | 全部可改造物品 |
| `tconstruct:modifiable/melee` | 近战武器 |
| `tconstruct:modifiable/ranged` | 弓、弩、标枪等远程 |
| `tconstruct:modifiable/armor` | 盔甲 |
| `tconstruct:modifiable/harvest` | 镐、锤、斧、镰等采集工具 |
| `tconstruct:modifiable/bonus_slots` | 匠魂认为"能加槽位"的全部工具 |

### 按具体物品

```json
"tool": { "items": ["tconstruct:pickaxe", "tconstruct:hand_axe"] }
```

### 按材料

```json
"tool": { "type": "tconstruct:has_material", "material": "tconstruct:wood" }
```

`material` 还可写完整谓词，例如匹配多个材料：

```json
"tool": {
  "type": "tconstruct:has_material",
  "material": { "type": "tconstruct:id", "id": ["tconstruct:wood", "tconstruct:stone"] }
}
```

### 按已有强化 / 属性

```json
"tool": { "type": "tconstruct:has_modifier", "modifier": "tconstruct:reinforced", "check": "upgrades" }
"tool": { "type": "tconstruct:stat_in_range", "stat": "tconstruct:durability", "min": 1000 }
```

- `has_modifier` 的 `check` 是**必填**的，取值 `upgrades`（只查强化槽里的）或 `all`（查全部强化）。
- `modifier`、`material` 这类字段既可以直接写字符串（单个 ID），也可以写完整谓词对象。

### 组合与取反

```json
"tool": { "type": "mantle:and", "predicates": [ { "tag": "tconstruct:modifiable/ranged" }, { "type": "tconstruct:not_broken" } ] }
"tool": { "type": "mantle:or", "predicates": [ { "tag": "tconstruct:modifiable/armor" }, { "tag": "tconstruct:modifiable/harvest" } ] }
```

取反建议用括号写法，避免不同版本对字段位置的要求差异：

```json
"tool": {
  "type": "mantle:inverted",
  "predicate": { "tag": "tconstruct:modifiable/armor" }
}
```

> `mantle:inverted` 在原版匠魂里是把子谓词字段**平铺**在同一层的，上面这种嵌套写法更直观也更通用；
> 如果日志报 `inverted_type` 相关错误，改成平铺形式即可。

### 优先级怎么配合

同一把工具命中多条规则时，`priority` 大的赢；相同优先级则加载顺序不确定，**所以请把 `priority` 显式写清楚**：

- 具体规则（按材料、按单个物品）用**正数**，如 `50`、`10`
- 兜底规则用**负数**，如 `-100`

## 4. 完整示例：1~4 级给强化槽，5 级起让玩家选

这份配置正好覆盖"按等级区间给" + "玩家自选" + "不同工具不同槽位"：

```json
{
  "priority": -100,
  "xp": { "base": 500, "multiplier": 2.0 },
  "max_level": 20,
  "slots": [
    { "levels": { "min": 1 }, "mode": "grant", "slots": ["upgrades"] }
  ]
}
```

```json
{
  "priority": 10,
  "max_level": 20,
  "slots": [
    { "levels": { "min": 1 }, "mode": "grant", "slots": ["upgrades"] },
    { "levels": { "min": 10 }, "mode": "choose", "slots": ["abilities", "upgrades"] }
  ]
}
```

完整可用的示例包在 `examples/datapack/tinker_leveling_example/`，直接拷进存档 `datapacks/` 就能用。

## 5. 配置文件（`config/tinkerleveling-server.toml`）

数据包没写到的部分从这里取默认值：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `maximumLevels` | `0` | 全局等级上限，`0` = 无限。数据包的 `max_level` 只能在此之下再收紧。 |
| `defaultBaseXP` | `500.0` | `xp.base` 缺省值。 |
| `levelMultiplier` | `2.0` | `xp.multiplier` 缺省值。 |
| `allowArmorExploits` | `false` | 允许非生物伤害（摔伤等）也算盔甲经验。 |
| `showDatapackSource` | `false` | 在工具提示里显示当前生效的规则 ID，调试用。 |
| `debugLogging` | `false` | 每次升级打印命中规则与槽位发放情况。 |

---

## 6. 玩家侧表现

- 升到配置了 `choose` 的等级时，客户端会弹出 **"升级奖励"** 界面。
- 界面列出每个可选项及剩余数量，点击按钮领取 **1 个**。
- 「稍后再选」可以关掉界面，**等下次升级时再弹**；这期间该工具不再涨经验。
- 只剩一个可选项时自动发放，不会打扰玩家。

## 7. 代码位置（改逻辑时看这里）

| 文件 | 职责 |
|---|---|
| `data/LevelingRules.java` | 数据包加载器、规则匹配、经验曲线、槽位奖励解析 |
| `data/SlotTypeLoadable.java` | 槽位类型解析与别名、拼写校验 |
| `ModToolLeveling.java` | `addXp` 升级流程、`addVolatileData` 把槽位写进工具、待选槽位队列 |
| `TinkerPacketHandler.java` | 升级提示、弹窗下发、玩家选择回传 |
| `client/SlotChoiceScreen.java` | 选择界面 |
| `capability/DamageXp.java` | 击杀伤害经验结算 |

### 数据存储（工具 NBT）

| 键 | 内容 |
|---|---|
| `tinkerleveling:level` | 当前等级 |
| `tinkerleveling:xp` | 当前等级内的经验 |
| `tinkerleveling:uuid` | 工具身份，用于把击杀伤害经验写回正确的工具 |
| `tinkerleveling:bonus_slots` | 已获得的槽位，`{"upgrades": 3, "abilities": 1}` |
| `tinkerleveling:pending_slots` | 待玩家分配的槽位，格式同上 |
| `tinkerleveling:bonus_modifiers` | **旧版遗留键**，工具被读取时自动迁移到 `bonus_slots` 并删除 |

### 槽位是怎么真正加上的

`addVolatileData` 在每次重建工具数据时，把 `bonus_slots` 里的计数按槽位类型写进 volatile data 的槽位容量，与匠魂
`ModifierSlotModule` / 强化配方加的槽位叠加。因此数据包给的是**额外槽位**，不会覆盖工具自身的槽位。

### 从 0.5.x 升级的注意事项

- 旧 NBT 键 `tinkerleveling:bonus_modifiers` 会在工具被读取时自动迁移成 `bonus_slots` 并删除，
  **老存档的槽位数量不会变**。
- Java API 有破坏性改动：`ModToolLeveling.getXpForLevelup(int, Item)` 现在接收 `IToolStackView`，
  `TinkerConfig.getBaseXpForTool(Item)` 已移除。若有附属模组调用了这两个方法，需要同步修改。
